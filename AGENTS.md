# charm-bak: agent notes

The name doesn't tie it to an engine, and the prefix is a nod to Charm. Backs up directories that aren't in iCloud to S3 or B2, using restic as the engine. Two halves: a Swift menu bar app that schedules and runs every restic call, and a Charm (Bubble Tea) TUI that browses, restores and edits sources by talking to the app over a Unix socket. Design detail: `docs/design.md`. `CLAUDE.md` is a symlink to this file; edit this one.

What was tested on macOS and restic, and what it means for the design, is in `docs/notes.md`. Read it before proposing a different approach.

## Goal

A TUI in the style of Alok's other Charm tools for: choosing source directories, seeing backup status and last run, browsing snapshots, restoring single files or whole trees, and diffing a snapshot against the live directory to cherry-pick changes. Compression, incremental snapshots and easy restore are the core requirements. Out of scope for now: AWS-style management of buckets, anything beyond restic's own features.

## Decisions so far

- **Engine: restic** (decided 2026-11-19). Chosen for its byte-level repository format spec, changelogs that say who a data-risk bug affects and how to repair, and verification of files before upload since 0.16.4. Repository formats differ between engines, so the engine choice locks in the format. Use the default compression (`auto`), never `max` (restic's own past corruption bug was `max`-only). The full comparison of engines is in the private notes.
- **Storage: S3** (Alok, 2026-11-19: he already has S3; Backblaze B2 was considered, cheaper but a second provider). Which account and bucket is still open. Storage class: S3 Intelligent-Tiering via a bucket lifecycle *transition* rule (Alok, 2026-11-22, at ~155 GB; replaces plain Standard): objects unread for 30/90 days move to the instant-access cheaper tiers, no retrieval fees, no minimum-duration charge when prune deletes. Never enable Intelligent-Tiering's optional Archive/Deep Archive tiers, and no Glacier classes: restic must read the repo to restore and prune. No lifecycle rule that expires objects: restic manages object lifetime. Credentials: a dedicated, long-lived, narrowly scoped key (unattended backups can't use expiring SSO/`aws login` credentials). Repo password in the Keychain via `--password-command`, never in a file.
- **Three parts (decided 2026-11-19, revising the Swift-core plan): a Go daemon, a Swift menu bar shell, a Go TUI.**
  - **`charm-bak-daemon` (Go)** owns everything on its machine: sources, schedule, retention, run history, pins, notes, the repository and its credentials, the scheduler and job queue, and **every** restic call (behind its `Engine` interface). Same binary on every machine: the Mac and Linux remotes (`GOOS=linux`). Shares `internal/protocol` with the TUI, so there's one copy of the wire types.
  - **`charm-bak.app` (Swift, thin)**: menu bar (status dot, pause, notifications from events), login item (`SMAppService`), signed bundle. It ships the daemon inside the bundle (`Contents/MacOS/charm-bak-daemon`) and starts it as a child, so the daemon inherits the app's Full Disk Access (tested: children inherit, TREK-11). The menu is just another socket client.
  - **TUI (Go)**: a pure client of the local daemon. No credentials, no repository access, no network connections of its own.
  - Why Go for the daemon: one static binary for every OS, one protocol implementation, Alok's stack; the Swift reasons (menu bar, login item, notifications, a signed bundle for Full Disk Access) only ever applied to the shell. The first core was written in Swift (`app/Sources/CharmBakCore`) and is being ported; delete it once the Go daemon passes the same tests.
- **TUI ↔ daemon: Unix socket, newline-delimited JSON** at `~/Library/Application Support/charm-bak/app.sock`, mode 0600 (file permissions are the auth). Request/reply by `id`, plus pushed events on a subscription. If the daemon isn't running, the TUI says so and offers to `open -a` the app. Protocol in `docs/protocol.md`.
- **Remotes (multi-host): paired daemons, no SSH** (Alok: no SSH keys or separate config). Each machine runs its own daemon and backs up on its own schedule whether the Mac is on or not; the TUI configures it through the Mac's daemon, which relays requests (with a `host` field) to paired remotes and passes their events through. Pairing: the TUI's **Add Remote** (`r` while the cursor is in the Sources column, on every row and header; `addremote.go`; moved from the menu bar, Alok 2026-11-23; `r` is Restore in the other columns) → host name → the Mac shows one command (click or `c` copies), then waits live ("waiting for wren…", then "paired; connecting") and, once the new machine answers, opens the setup flow for it; the popup keeps one height throughout. **Mac remotes** (Alok, 2026-11-23): the same command; the script branches on `uname -s`. A Mac gets `/Library/Application Support/charm-bak/charm-bak.app` (a minimal bundle, `io.github.alokdhir.charm-bak.remote`, signed like the app, carried in `Contents/Resources/darwin-<arch>/` and served as a tar.gz at `/m/<code>/<arch>`), state in `…/charm-bak/state/`, and a root launchd daemon `/Library/LaunchDaemons/io.github.alokdhir.charm-bak.plist` (`-listen :7457`, PATH with Homebrew's bin, KeepAlive only on failure). A remote is any daemon run with `-listen` (or not on a Mac): secrets in files, self-update, uninstall. Full Disk Access can't be requested by an app (no prompt, no API): `status` reports `full_disk_access` (macOS: can it open the system TCC.db), and when a newly paired Mac lacks it, Add Remote shows a step: Enter runs `access_settings` there (Finder reveals the bundle and System Settings opens at Full Disk Access, in the logged-in user's session via `launchctl asuser`), then polls every 2s and goes on to the setup flow when the grant lands; `s` skips, and the header then reads "disk access" (Enter there reopens the step). Tested on a second Mac (`basement`, a MacBook, 2026-11-23): the install command, pairing, Full Disk Access granted by hand in System Settings, the repository set up through the TUI, and Remove with delete. Not separately confirmed: that the grant let a backup read protected folders there, and the TCC.db check's answer before the grant. Self-update sends a Mac remote the whole bundle (a tar.gz, swapped in beside the old one), so its Info.plist and signature seal follow the executable; a re-signed build always has a new hash, so every app build updates Mac remotes. The command to paste on a remote is `curl --pinnedpubkey … https://<mac>:7458/i/<one-time code> | sudo sh`; on Linux it downloads the daemon from the Mac (carried inside the app), installs a systemd service, and pairs by proving the one-time code (a pairing code works once; a Repair code pairs nothing and serves the script and daemon for its 10 minutes). Afterwards mutual TLS between pinned per-daemon keys (Mac's in the Keychain, the remote's root-only). Remote credentials (its own IAM user, repo password) live on the remote in root-owned 0600 files in its state dir, `/var/lib/charm-bak` beside the database and identity key (Alok, 2026-11-22: no systemd dependency; `/var/lib/<app>` is where NetBird and Tailscale keep theirs); the Mac can create the IAM user and send the key during pairing. Sources grouped by host in the Sources column. Details in `docs/design.md`. Ports (in the README's "Remotes and your network"): the remote listens on TCP 7457 and must be reachable from the Mac; the Mac listens on 7458 only while Add Remote is open. The Mac has no permanently open port, so a remote can't announce itself: the Mac retries one that isn't answering every 5s at most (`remoteRetryMax`; Alok, 2026-11-24, chose that over an always-listening port on the Mac). **The Mac reads every remote's repository itself** (Alok, 2026-11-24: a machine that's off or dead is when its backups are needed most, and browsing never needed its daemon): `remoteread.go` answers `snapshots`, `ls`, `changes` and `dump` for a remote by running restic here against that remote's repository, with the location saved from the remote and the Keychain copies of its password and credentials (`charm-bak-repo/<host>`, `charm-bak-env/<host>` or `charm-bak-aws/<host>`, kept since the remote was set up through the Mac). The relay is only for what must happen on the remote: sources, schedules, keys, back up now, pins and notes, excluding, live listings and diffs. Each time a remote answers, the Mac saves its repository, sources, pins and notes (`remote_cache` table, dropped with the pairing), so an offline remote's sources still list and its snapshots keep their pins and notes. Nothing labels this; the hero's Daemon already says a machine is offline. Actions that need the remote carry `action.needs`: while the machine is offline they're dimmed in the action bar and open a dialog saying so (`offline.go`). Restoring a remote's snapshot asks "Restore to": that machine (its daemon, a path there or in place) or this Mac (`restore` with `from`, a copy in a folder); offline, this Mac only. A remote configured by hand, with no password on the Mac, is still relayed and can't be browsed while off.
- **Scheduling: each daemon's own timer**, not launchd calendar jobs or systemd timers: it checks what's due each minute, so runs missed during sleep or power-off catch up on wake. One restic job at a time (repo locking); the TUI's "back up now" queues a run in the app. Each run: `backup`, then `forget` with the source's retention (no `--prune`). `prune` runs separately, weekly and overnight, because it locks out every read (TREK-12); the TUI shows "busy: pruning" meanwhile. Rule (`maintenanceDue`): a week after the last prune that succeeded, between 01:00 and 05:00 local, or at any hour once it's more than a day overdue (a machine that's off at night); a failed or cancelled one is retried after an hour. A backup cancelled by the daemon shutting down leaves no run, so it's due again at the next start. Paths the daemon hands restic as patterns (`rewrite --exclude`, `restore --include`, and the anchored excludes `selection.go` compiles) have `\ * ? [` backslash-escaped, since restic reads them as globs (tested 0.19.1: unescaped, `[2024] Taxes` matched `2 Taxes`). Weekly `check --read-data-subset`. Daily, each daemon backs up its own database (`statebackup.go`, job kind `state`): `VACUUM INTO` a copy `charm-bak.db.bak` beside it, backed up under tag `charm-bak:state` with retention 7 daily / 4 weekly / 12 monthly; not a source, not shown under untagged; restore with `restic restore latest --tag charm-bak:state` (Alok, 2026-11-22). Not in it: identity key and secrets.
- **A source is a restic tag.** restic has no source object; snapshots carry host, paths and tags, and `forget` groups by host+paths by default. charm-bak tags every snapshot of a source `src:<id>` and runs retention as `forget --tag src:<id> --group-by tags`, so editing a source's paths doesn't silently start a new retention group. Snapshots without a charm-bak tag, and ones whose source was removed keeping its snapshots, show under an "untagged" pseudo-source, never hidden.
- **What a source can be** (tested on restic 0.19.1): one or more paths, exclude globs (`**`, anchored or floating, `--iexclude` for case), and `!` re-includes, which only work if the folders above them aren't excluded outright: exclude a folder's contents (`dir/*`) and then `!dir/child` (tested 2026-11-20; excluding `dir` itself and re-including a child backs up nothing). `internal/backup/selection.go` compiles ticks to that form and back. Defaults for every source: `--exclude-caches`, `--exclude-if-present .nobackup`, and on macOS/Windows `--exclude-cloud-files` (restic on Linux doesn't have it: unknown flag, every backup failed on pantry until `backupFlags` made it per-OS). The add/edit picker is a tick tree over the live disk, files and folders (`[x]` in, `[ ]` out, `[-]` mixed; space flips an item and everything inside), held as a `backup.Selection` that compiles to paths + anchored excludes + re-includes; patterns that aren't one path (`node_modules`, `*.tmp`) are the "Also skip" list in the source form (one per row; a comma is part of a pattern). `Selection.Exclude(p)` always excludes (the tree's `x`); `Toggle` is the picker's space. A `!/abs/path` re-include typed by hand is kept as a pattern unless a ticked-out folder is above it. A source that is one file opens its tree at the parent folder. restic stores absolute paths, so the tree columns open at the source's folder (or the paths' common parent), skipping the empty folders above.
- **Mount: deferred.** `restic mount` needs FUSE (no WebDAV option that we know of; unverified), and FUSE's extension only loads after a restart. Alok doesn't restart except for new kernels: never ask him to. Browsing, preview and restore don't need a mount. Retest FUSE after the next macOS update (TREK-2); until then no Mount button.
- **Layout: browser first, settings in popups** (bidkit's pattern, not a menu screen). Columns: Sources | Snapshots | tree columns, preview or diff rightmost, sliding left when deep. A machine's things live on its header in Sources, shown even with one machine (Alok, 2026-11-24, replacing the Repository popup on `o`, a read-only dead end): its repository (location, size, last check) in the hero, all of it (credentials' source, cleanup, check, next upkeep, defaults) in the info popup (`i`), and Edit (`e`) opens the machine popup (`machine.go`): the defaults its sources inherit, and for a remote an Address tab (address, Repair). Setup opens by itself on first run, and Enter on a header that says "setup" reopens it. Per-source policy popup on `e`, showing each field's effective value and where it's inherited from. Popups never outgrow the terminal: long skip lists scroll in a window ("↑ n more"), source folders show at most 4 rows, and `compositeOverlay` cuts anything still too tall, keeping its hints line. Below the minimum size (100x20) only quit works. A question that arrives while another popup is open waits until it closes (`a.ask()`); replies carry their host or origin and are dropped when the popup they were for is gone. Defaults: schedule ("Back up"), retention ("Keep"), and Skip. **Keep is one choice** (Alok, 2026-11-24: six per-period counts are fussier than anyone needs; Time Machine has no setting, Backblaze one): 1 month, 1 year (the built-in default for new machines), 3 years, forever, or custom (the six counts, each explained); a source's form adds "default (…)" first. Presets (`keep.go`) all keep every backup from the last day (newest 10, 24 hourly), then 30 dailies, 12 weeklies, then monthlies (12 or 36), and forever adds yearlies with restic's `unlimited` (`protocol.KeepUnlimited`, -1 on the wire). restic's periods are calendar ones (Mon–Sun weeks) and it keeps the newest snapshot of each (tested 0.19.1); the schedule, by contrast, runs an interval after the last run ended. Machines that already had sources when the default changed keep the old one, saved as theirs (store migration). Skip: patterns every source skips before its own (none built in: Alok, 2026-11-22, dropped a built-in `*.log`, skips belong to the sources they're for; each backup passes `--exclude` for the defaults' patterns, then the source's).
- **Hero + action bar** (charm-aws style) above the columns. Hero is a borderless label/value grid (charm-aws `renderHeroGrid`, spacing only, no separators): both rows share column widths, sized over every item in the focused list so the grid holds still as the cursor moves; when too wide it drops `optional` cells (ones the info popup also shows) before cutting the widest. Two rows: line 1 describes the focused column's selection (source: last result, next run, retention; snapshot: time, duration, size and what that run added ("12.0 GB, 4.2 MB new"; the Snapshots column shows the added size too, since every snapshot holds everything), note, pin (no keep reasons: restic moves them to newer snapshots every run, so they only confuse; the info popup still lists them); file: size, mtime, comparison with live); line 2 is the selected row's host: its repository's stored vs logical size and its daemon's state (this Mac's from `status`, a remote's from its status, fetched with the sources and on its `state_changed`). Sizes are decimal (1000s, like Finder and S3). A source's Last run reads "✓ 20m ago, took 18m54s", and Schedule's next run names the day when it isn't today ("tomorrow 14:29"). The action bar is right-aligned, lists the focused column's keys (`[A]dd`) plus `[I]nfo` when there's something to show, and its letters work regardless of focus. It's a key guide, never focused (Alok, 2026-11-24: its buttons move with the selection, so walking to one was slower than pressing the letter). Focus: `↑` from a column's top row enters the hero's bottom line, `↓` from there goes back. Tab jumps from anywhere straight to the hero's first stop, and Tab or Esc goes back to the columns (Alok, 2026-11-22: from a remote's source, walking up through every row above was the only way); the hero's bottom edge says `tab edit` (`tab back` inside it). The hero's second row is never cut: when the grid is too wide, the first row's cells give way. Inside the hero, arrows are spatial: each moves to the nearest focusable thing in that direction (by screen position) and does nothing if there isn't one. Left/right never wrap to another line. The footer's left end says what's running on any machine ("⠋ backing up home 42% · ^T", or "2 jobs running"), then the latest status; **^T** lists the running jobs live, Enter goes to the source, `c` cancels after asking (Alok, 2026-11-23, replacing the cursor's "x of y"; charm-aws's task list). Costs about 5 rows; minimum height about 26.
- **Focusable hero fields.** Rule: a field gets a cursor stop if and only if Enter does something there; moving the cursor and pressing Enter are cheap, so err toward including. Stops: schedule (picker), retention (picker), last run (always; run details, retry when failed), app status (always; launch when stopped, run log and pause when running), snapshot description and pin, a file's comparison with live (diff, only when they differ). Sizes, dates and dedup figures are not stops. Pickers are the same editors the source popup uses, never a second implementation. Revisit once real data exists.
- **Source keys** (Sources column): `a` add, via charm-aws's file picker with multi-select, rooted at `~`, then a confirm popup showing inherited policy with per-field override and "back up now" on by default; `e` edit that source's policy; `x` remove (stops backups; asks keep snapshots, the default, or delete them, with a second confirm); `b` back up now. `e` in other columns acts on their selection (snapshot: description, pin). `c` on a snapshot (**Changes**, `changes.go`; Alok, 2026-11-24, replacing Diff there: how a snapshot's top folder differs from the disk wasn't the useful question) lists what it added, removed and changed since the snapshot before it, through the whole tree, and muted with a `·` the files it only touched: same contents, different details like a timestamp (Alok, 2026-11-24: an hourly `/etc` snapshot said "0 changed" beside 140 KB new, which was folder records for two touched files) (`changes`: `restic diff --metadata`, cached); it reads the repository, so it works for an offline machine. `d` (Diff against the live disk) is for files and folders in the tree. It opens from the info popup too, in front of it, and closing it leaves info there. (Info has no changed-files count: restic's own summary counts files re-read for a metadata change, which disagreed with the list.) Skip patterns (a source's Also skip, the defaults' Skip) are a list, one pattern per row (`patternlist.go`; Alok, 2026-11-24: commas and spaces in one field were unreadable): ↑↓ through them, Enter edits, `x` removes, the last row adds; the help line says what the selected one matches (restic: no leading `/` = any depth, tested 0.19.1). In the tree, `x` excludes the selection from its source from the next run on, or also from past snapshots (`source_rewrite`: a `rewrite` job, then prune; asks twice, Cancel preselected; notes and pins follow the rewritten snapshots); `f` (Snapshots and tree, this Mac's sources only) reveals the live copy in Finder, or the nearest folder above it still on disk. A remote's Edit popup has an Address tab with Repair (↓): `host_repair`'s command reinstalls its daemon there, keeping its state.
- **Notifications: macOS only** (Alok, 2026-11-20: toasts would duplicate them). The menu bar app posts a notification for failed runs, TUI open or not; successes stay quiet. One per machine (Alok, 2026-11-22, after six sources failing on one locked repository gave six): failures arriving within 5s are gathered into one ("6 backups on pantry failed", names and the shared reason), and it goes away once each has had a good run. No TUI toasts or catch-up toast. Also posted: a finished `rewrite` (removing something from past snapshots), since it's long and asked for by hand. On Windows, restic can't store App Execution Aliases (the zero-byte stubs in `AppData\Local\Microsoft\WindowsApps` that start Store apps: "unsupported file type irregular", restic #22113), so those errors are ignored there (`appAlias`); the folder is still backed up, so a real file in it is saved or reported (Alok, 2026-11-25, rather than skipping the folder). A backup that couldn't read some files is a warning, not a failure (Alok, 2026-11-25): health `skipped`, an orange ⚠ and "N files skipped", and it's notified like a failure ("Backup of games on den: 80 files skipped"). The hero says only the state ("✗ just now, failed"); the reason belongs to the notification and ^N. The TUI's **^N** lists past notifications, rebuilt from every answering machine's `history` (failures, skipped files and finished rewrites, last 30 days, newest first), after charm-aws's notification list (Alok, 2026-11-23). Enter opens one's details (`noticedetail.go`, Alok 2026-11-25): when, how long, the snapshot, and the whole reason, or every skipped file with restic's reason (`run`, fetched then: up to 1000 per run, kept beside the run, not sent with history); Enter there goes to the source, Esc back to the list. **A click on a notification opens its details** (Alok, 2026-11-25): each notification carries its machine and job; the menu bar app sends `notice_show`, the daemon keeps it two minutes and announces it, and the TUI that claims it (`notice_take`: a running one at once, a new one when its machines are known) opens ^N at it (a gathered notification opens the list); a popup being worked in stays, and the footer says ^N has it. Then the TUI is raised: exact in tmux, Terminal.app and iTerm2 (by tty) and in kitty with remote control on (`kitten @ ls` finds the window whose process is the TUI or an ancestor, `focus-window`; kitty's socket is `/tmp/kitty-<pid>`); without it, the terminal app is only activated. Inside screen (Alok's), the app raises the terminal the attached `screen` client runs in (the `SCREEN` server among the TUI's ancestors; with several clients, the one whose arguments name the session), and the TUI selects its own screen window when it takes the notification (`screen -S $STY -X select $WINDOW`: only it can read those; macOS doesn't expose another process's environment). A TUI that's running but can't be raised is never joined by a second one. The TUI offers the two kitty.conf lines once (`kittyhint.go`), when it runs in a kitty that doesn't listen (no `KITTY_LISTEN_ON`).
- **macOS is command and control; remotes can be anything** (Alok, 2026-11-20). The TUI, the menu bar app and notifications live on the Mac; a remote (Linux now, Windows maybe later) is only a headless daemon the Mac's daemon relays to, so the daemon must stay portable (secrets, service install, builds) while the shells don't. Remote failures reach Alok as the Mac's notifications.
- **Linux and Windows desktops: lowest priority** (Alok, 2026-11-20: everything else is finished first; EPIC-12). But when a decision comes up along the way, weigh them: keep platform specifics (Keychain via `security`, Full Disk Access, `open`, socket paths, terminals) behind small seams rather than spread through the core, and prefer portable Go over macOS-only shortcuts when the cost is about the same.
- **Integration is the restic CLI with `--json`, run by the daemon only, behind its `Engine` interface** (Alok, 2026-11-19): the core never builds a restic command outside the engine. A second engine (Kopia) would be another `Engine` implementation with no protocol or TUI change; not planned. Don't import restic internals as a library.

## Architecture

- `main.go` (`-env` runs the bundled `charm-bak-daemon -env`, found next to its resolved executable) runs `ui.NewConnectRoot` with a `Connector` (dial via `internal/client`, launch via `open -b io.github.alokdhir.charm-bak`); `--fake` runs `ui.NewRoot(ui.NewApp(backup.NewFake(...)))` on fixture data instead.
- `internal/backup`: the `Repo` interface the UI reads (Status, Sources, Snapshots, List, Read) over `internal/protocol` types, `Root` (where a snapshot's tree opens: its one path or the paths' common parent, since restic stores absolute paths) and `Join`; `fake.go` is deterministic fixture data built from a passed-in `now`, shaped like the app's replies. **No charm/lipgloss imports and no human-facing wording here**; `internal/ui` decides how things look (charm-aws's "Keep Layers Apart").
- `internal/client`: the socket client, implements `backup.Repo`. One connection, a reader goroutine routing replies by id (concurrent loads share it), redial on the next call after the app restarts, `hello` version check (`unsupported_protocol` surfaces as `*protocol.Error`), `List` fetches every page, `Subscribe` opens a second connection for events. `live_test.go` walks the installed app's data with `CHARM_BAK_LIVE=1`.
- `internal/ui`: `root.go` sets alt-screen and the OSC 11 background (never a lipgloss background wrap). `connect.go`: until the app answers, Root shows only the connect screen (app not running: Enter starts it and retries for 15s; protocol mismatch: says which side to update). `app.go` is the model: focus `area` (columns, hero), a `cursor` per list, and `levels` (one per open tree column). Multiple hosts: `loadSources` asks `hosts`, then each answering host's sources (every Source carries its `host`); `sourceKey` (host/id) identifies a source, `srcRepo()` (`Repo.ForHost`) sends snapshot, tree, restore and source changes to the selected source's host, Add goes to the selected row's host when it's answering (`addHost`): the folder picker lists that host's disk through its daemon (`ls` with `snapshot: "live"`) or, for this machine, reads it directly, and starts at `/` on a remote (`homeFor` is "" there, so no `~`); the Sources column shows a header per host, even with one: orange rows (`FileTitleStyle`) with ▾/▸ that the cursor stops on (`srcrows.go`: `srcCur` indexes `srcRows()`, headers included; `selSource`/`selHost`), Enter folds or unfolds (→ unfolds, ← folds; folds last for the session), a folded header shows its source count; a remote's link is one mark: green ✓ connected, yellow spinner connecting (the same spinner, ticking only while a host connects), red ✗ offline (the hero's Daemon says "offline" or "connecting" in a word; the info popup's Link has the reason); on a header the hero shows Host, Sources, Where and Repository (no Link cell: the second row's Daemon carries a remote's state), the Snapshots column is empty, and the actions are Add, Edit (the machine popup; a remote's has an Address tab: `host_set`, `hostform.go`; also Enter on the hero's Where), for when the remote's IP changes (Alok, 2026-11-22); the pairing key stays, so only the same machine can answer there; and Remove (`x`, `hostremove.go`; Alok, 2026-11-23): takes the remote away altogether through `host_remove`: the controller sends it `uninstall` (it pauses, deletes its own snapshots and prunes if asked, before replying, and refuses to go on if that fails; then `main` disables and deletes its systemd unit, executable and `/var/lib/charm-bak`, and exits 0), then unpairs it; keep backups is the default (the Mac keeps its Keychain copies of that host's secrets so they can still be opened), delete asks twice and drops them, and also deletes the AWS user charm-bak made for it (`charm-bak-<host>` at `/charm-bak/`, with the key manager; Alok, 2026-11-25), only when charm-bak made that machine's key (`aws_made_keys` remembers each made key's ID) and the user still has it: a key typed by hand or replaced since leaves IAM alone; without a key manager it says to delete it by hand; a remote that isn't answering can only be unpaired, and the TUI shows the commands to run there; events with a `host` only refresh sources and that host's snapshots, never the hero's job. Tree items are `node`s: an entry plus its snapshot and absolute path; `node.key()` (snapshot + path) identifies loads. Every load is an async `tea.Cmd` whose message says what it was for (source id, node key); `Update` drops replies the cursor has moved past. Moving a cursor reloads everything to its right (`refreshFrom`). Only one tree level past the focused column is ever loaded (`nextLevel`): the pane right of the walked columns shows the selected folder's listing or the selected file (details plus contents via `Repo.File`), in the same place either way, so file vs folder never changes the layout's shape. Never load deeper than that: auto-opening first children was a real bug (TREK-9). `columns.go`: `columnLayout` slides walked columns off the left until the pane gets `previewMin`, never sliding off the focused column; what slid off shows as a muted breadcrumb (`source › snapshot › folder/`, cut at the front) at the left of the action bar's row; `renderFile` is the file pane. `hero.go`: lines are `seg`s, and a seg with a `stop` is a cursor stop. `actionbar.go`: `actions()` per column, hotkeys work from any area, footer is status only. `keys.go` + `help.go`: `helpBindings` is the one list help renders.
- `internal/ui/styles`: Charmtone color roles, one meaning each. One cursor look everywhere (`SelectedStyle`: list rows, hero stops); a focused column's title is colored text, never a filled bar. The app name sits in the hero box's top edge. A source's hero row is Source, Size (its newest snapshot, from `Source.bytes`, which the daemon takes from the last run that made a snapshot), Last run (never cut, `whole`; a backup in progress shows only in the Daemon cell, Alok 2026-11-25), Schedule, and Retention on the second line beneath Schedule (`under`; Alok, 2026-11-25: that line had room; the cell beneath Last run stays empty for now) (shown as its reach, e.g. "3 years (default)"; the rule is in the editor and info popup). The hero's second row is Stored (deduplicated, compressed size, with the uncompressed size in parentheses) and Daemon (its state), with room for more; the destination is not in the hero (set once, per host): it's in a source's info popup and on its machine's header; the first tree column is titled "Files", deeper ones "in <folder>/".
- `internal/protocol`: the socket wire format (`docs/protocol.md` is the contract). `testdata/protocol/*.json` has one example per method, error and event; `TestFixturesMatchTypes` decodes each strictly and round-trips it, and fails if a method or event has no example. The Swift side decodes the same files. Change the doc, the types and the examples together.
- `internal/daemon` + `cmd/charm-bak-daemon` (Go, the daemon): `engine.go` (the `Engine` interface, `RepositoryConfig` with Keychain references, `EngineError`), `restic.go` (`ResticEngine`: every restic flag, JSON shape and exit code; SIGINT on cancel; all-zero retention is a no-op), `secrets.go` (secrets per run, as env for that process only: on the Mac from the Keychain via `security` (`KeychainRead`; `keychainAdd` writes through `security -i` on stdin so a value never sits on a command line); elsewhere from owner-only files `repo-password` (restic reads it via `RESTIC_PASSWORD_FILE`) and `aws` in `Core.SecretDir`, set by `main` to the database's directory when not on macOS), `reposet.go` (`repository_set`: a remote stores what it's sent in those files, optionally `init`s, drops caches; the controller sends it during `repository_setup` for that host and keeps its own copies of the secrets), `store.go` (modernc SQLite: settings incl. `defaults` and `repository`, sources with nil = inherit, runs, notes, pins; migrations by `PRAGMA user_version`), `cache.go` (every restic call costs ~0.8s of startup and index loading on S3, so the first folder opened in a snapshot starts one `restic ls` of the whole snapshot in the background (`Engine.Tree`, ~2s for 95k files) and later folders come from the cache, even during a prune; the cache is a SQLite database of its own (`treedb.go`, `cache/trees.db` beside the state database, not in the state backup; one gzipped row per folder, so a folder is read without holding its tree; up to 512 MB, least recently used snapshots dropped first; Alok, 2026-11-24), so a snapshot opened once stays instant across daemon restarts; listing a source's snapshots warms the newest one's tree; the same cache serves this machine's repository and the remotes' it reads; without a cache database (tests) the 8 most recently used trees stay in memory; snapshot lists cached per tag until any job finishes or 10 minutes pass; the repository size for `status` (`Engine.Stats`, `restic stats --mode raw-data`, ~1.5s) is read in the background on first ask and whenever the queue empties after a non-restore job, then pushed as `state_changed`; reads use `--no-lock`, see `docs/notes.md`), `core.go` (`Core`: every protocol method, job queue one at a time with events and cancel, `Tick` scheduler with weekly prune + 5% check, reads `busy` during prune, keep-reason cache, live diff), `peers.go` (pairing and relay: each daemon has an ECDSA P-256 identity key (`identity.pem` beside the database, owner-only; the pin is curl's `sha256//base64` of the SPKI); the `peers` table holds remotes (with an address) and controllers (without); `ListenRemote` serves the same protocol over TLS 1.3 to pinned peers only; the controller relays requests whose `host` names a remote (`client.Forward`, connected lazily) and follows each remote's events, republishing them tagged with the host, plus `host_changed`; flags `-name`, `-listen`, `-pin`, `-add-remote name,host:port,pin`, `-add-controller name,pin`, `-peers`, `-remove-peer` for doing it by hand; keys are ECDSA P-256 (macOS's curl can't handshake with Ed25519); `pairing.go` is `pair_start` (the TUI's Add Remote): a one-time code, a TLS server on 7458 serving the install script, the Linux daemon from `Contents/Resources/linux-<arch>/` (built by `app/build.sh`) and the pairing call; the remote side is `-pair <url> -controller-pin <pin>`, run by the script, which then writes `/etc/systemd/system/charm-bak.service` (`-listen :7457`, `StateDirectory`/`RuntimeDirectory`) and enables it; `StateDir` and `protocol.SocketPath` are per OS: `/var/lib/charm-bak` and `/run/charm-bak/daemon.sock` for a root Linux daemon), `logging.go` (the daemon's own log, `daemon.log` beside its database: `/var/lib/charm-bak/daemon.log` on a Linux remote, `~/Library/Application Support/charm-bak/daemon.log` on the Mac; rolls to `daemon.log.1` at 5 MiB; also to stderr (a remote's journal) unless stderr is that same file, as on the Mac where the app points the daemon's stderr there for crashes; logs start/stop with version and build, each job's start and outcome, remotes answering or not, refused connections, pairing, repository/default/source changes, self-updates; never secrets), `update.go` (self-update: on every connection to a remote, the controller compares the remote's hello `build`/`os`/`arch` with the stripped Linux daemon it carries and, if different, sends it with `self_update`; the remote verifies, renames over its executable (`Core.UpdatePath`, read at startup since Linux reports a replaced executable as deleted) and `main` re-execs it after a clean shutdown, no service manager involved), `server.go` (Unix socket, owner-only, stale cleanup, refuses a second daemon, half-closed clients still answered; `Run` = serve + tick every minute). Flags: `-socket`, `-db`, `-exit-with-parent` (shut down when stdin closes), `-env` (print the repository as shell exports for running restic by hand; the secrets are Keychain reads that run at eval time, never printed). Tests run it through `internal/client` with real restic, under `-race`.
- `app/` (Swift, the menu bar shell): `CharmBakCore` is only `Protocol.swift` (wire types mirroring `internal/protocol`, checked against `testdata/protocol` by `swift test`) and `DaemonClient.swift` (one short connection per request, one subscription for events; `hello` first on every connection; `notRunning` only when connect fails, `noReply` for a connected daemon that's slow or gone, so slowness never spawns a second daemon). `Sources/CharmBak/`: `CharmBakApp.swift` (menu: status dot and line, pause, Full Disk Access warning, login item; refreshes after daemon events except `progress` and each minute, one refresh at a time with requests coalesced so results apply in order; red when the daemon is unreachable past 20s, keeps exiting, or speaks another protocol version), `Daemon.swift` (`DaemonSupervisor.shared`: `ensureRunning()` at launch, every minute and whenever the menu's event connection drops starts the bundled daemon if nothing accepts connections on the socket, so a hand-started daemon that goes away is replaced; the child gets a stdin pipe and `-exit-with-parent`, so it shuts down however the app ends; quick exits (under 10s) restart with backoff 5s→60s and set `problem` from the last `daemon.log` line; `stop()` on `applicationWillTerminate` sends SIGTERM, SIGKILL after 10s, and nothing starts afterwards), `Notifier.swift` (macOS notifications for failed runs from `job_finished` events, never restores, cancels or incomplete runs; one per machine, failures within 5s gathered into one, repeats replace it, removed once everything in it has run OK; click opens the TUI; `--notify-test` at launch posts a sample), `Terminal.swift` (the menu's **Open TUI**: if a TUI is already running (a process whose executable resolves to the bundled `charm-bak-tui`, PATH-link launches included) it brings that one forward instead of opening another, by the TUI's tty: inside tmux, tmux selects its pane and the terminal showing that session is raised by the client's tty; Terminal.app and iTerm2 select the tab with that tty through AppleScript run by `osascript` (no automation entitlement on the app, so its signature and Full Disk Access are untouched; macOS asks once); other terminals get their app activated (exact for kitty and Ghostty, which Open TUI starts as an instance for the TUI); otherwise runs the bundled `Contents/MacOS/charm-bak-tui` in the terminal set by `defaults write … terminal <bundle id>`, else a known terminal that's running, else the system default for executables; kitty gets the binary as a document so a running kitty opens a new window, not a new instance, and `~/.config/kitty/launch-actions.conf` has a rule for `charm-bak-tui` that skips kitty's run-this-executable prompt and hold), `StrataIcon.swift`, `AccessProbe.swift`. `app/build.sh` builds the Swift app and the Go daemon, signs the daemon (`<bundle id>.daemon`) then the bundle with the Apple Development identity, installs `~/Applications/charm-bak.app`; keep the bundle ID and identity fixed or the Full Disk Access grant is lost.
- **Icon: strata** (Alok's pick over a pocket watch and a locket): a top slab over two layers. Menu bar is a one-color template image, except failed, which adds a coral dot. App icon is the strata in the Dolly-to-Charple gradient on a near-black tile.

## Conventions (inherited from bidkit and charm-aws)

- Build and verify: `go build ./... && go vet ./... && gofmt -l . && go test ./...` (`-race` for `internal/daemon` and `internal/client`), plus `cd app && swift test` when `app/` changed, all clean before a change counts as done. Try the live socket with `printf '%s\n' '{"id":1,"method":"status"}' | nc -U -w 1 ~/Library/Application\ Support/charm-bak/app.sock`.
- Every frame fits the terminal exactly (`TestFrameFitsTerminal`): a line too wide wraps, a frame too tall scrolls, and both corrupt the screen. Never `tea.Printf`, never let a library probe the terminal.
- Test logic that's invisible when wrong (layout math, stale-message handling, focus moves, health classification), not cosmetics. To eyeball rendering, use a throwaway `zz_tmp_dump_test.go` and delete it.
- Align with lipgloss tables, never `Sprintf`/padding (Alok, 2026-11-22: "we've talked about this"). Label/value rows go through `renderRows` (`internal/ui/rows.go`, borderless `lipgloss/v2/table`, values wrap under themselves); popups mixing rows with other lines use `formBuilder`. The hero grid is the one exception: it's measured per column because cursor stops and clicks need each cell's position.
- Search before writing a widget; reuse bubbles/v2 and the helpers here. Code copied in from bidkit or charm-aws is adapted and owned here, with no "copied from" comments.

## Long names, info, click-to-copy

- Names are cut in the middle, keeping the end (`midTrunc`), because version suffixes and extensions live there. Sources show by name in the Sources column and hero (their folders are in the info popup and the form). Tree columns size to their content within 18..40 cells (`treeColWidth`). The hero cuts only the name, so the rest of its line stays readable.
- `i`, or Enter on the name in the hero, opens the info popup: every field of the selection in full, wrapped at `/ - _ .`. Space opens and closes it too. While it's open, ↑↓ (and page keys) move the column's cursor and ←→ move across columns, and it follows, like Quick Look (Alok, 2026-11-24); ↑ on the top row stays in the column. Its height springs open and to each selection's height (`infoanim.go`, harmonica; only the height moves, Update drives it, render only reads it). Info taller than the screen scrolls (shift+↑↓ or the wheel; the title and hints stay, and the hints say there's more). `infoBody` (`infoLayout`'s lines, cut to the height and scroll being drawn) is the one layout used for both rendering and hit-testing. Walking with ↑↓ puts focus in the column, wherever info was opened from.
- **Click-to-copy, no copy key** (Alok's call: no undocumented magic keys). A click on the hero's name copies the selection's full live path; a click on an info row copies that row's whole value (all of its wrapped lines). Copy is OSC 52 with the `ESC \` terminator plus an audible cue and a footer flash (`clipboard.go`, ported from charm-aws). Clicks within 250ms of a focus report are ignored. Hit tests re-lay-out the view; render functions never record positions or mutate state.
- **Mouse tracking is always on** because the hero is always visible. Deliberate tradeoff: a plain drag no longer selects terminal text; shift+drag still does. Help says so.
